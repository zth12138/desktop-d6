# Desktop D6

Desktop D6 是一个 Windows 桌面摆件。它使用《以撒的结合》风格的 D6、底座和道具图标，让用户点击 D6 后随机替换桌面应用快捷方式的图标。

## 当前状态

目前已完成开发运行版，可以通过 Electron 启动并测试。Windows 一键启动的便携版和安装包尚未生成。

## 已实现功能

- 透明、无边框、始终置顶的桌面 D6 摆件。
- D6 在底座上方轻微上下浮动。
- 底座顶面带有独立阴影素材。
- 按住底座可以拖动摆件位置。
- 左键点击 D6，随机替换 Windows 桌面上的应用快捷方式图标。
- 默认模式会处理所有可用的 `.lnk` 桌面快捷方式。
- 可以从右键菜单手动选择一个桌面快捷方式并单独随机。
- 自动跳过文件夹、Windows 系统桌面图标和 D6 自身的快捷方式。
- 首次修改快捷方式时记录其默认图标位置，连续随机后仍可恢复默认状态。
- 图标缓存位置可以手动设置，默认位于程序目录的 `desktop-d6-cache`。
- 自动通知 Windows 刷新桌面图标。
- 支持外置 `collectibles` 文件夹，打包后用户仍可增删自定义道具图标。

## 操作方法

| 操作 | 效果 |
| --- | --- |
| 左键点击 D6 | 按当前模式随机桌面快捷方式图标 |
| 右键点击 D6 | 打开功能菜单 |
| 按住底座并拖动 | 移动整个桌面摆件 |

右键菜单包含：

| 菜单项 | 功能 |
| --- | --- |
| 恢复桌面默认图标 | 恢复所有由 D6 修改过的快捷方式到首次修改前的状态 |
| 手动选择快捷方式… | 选择一个 `.lnk` 快捷方式，将它设为后续点击目标；不会立即随机 |
| 当前手动目标 | 显示当前保存的手动目标 |
| 切换为全局随机 | 清除当前手动目标，让左键点击恢复全局随机 |
| 输出日志 | 默认关闭，勾选后将各环节耗时写入项目 `log/desktop-d6.log`；开关会保存 |
| 打开道具文件夹 | 打开程序当前读取的 `collectibles` 目录 |
| 设置图标缓存位置… | 选择以后生成的 ICO 文件保存目录 |
| 打开图标缓存文件夹 | 打开当前使用的缓存目录 |
| 恢复默认缓存位置 | 让后续图标重新保存到程序目录的缓存文件夹 |
| 退出 D6 | 关闭程序 |

## 开发环境启动

需要 Windows、Node.js 和 npm。在项目目录打开 PowerShell：

```powershell
cd "D:\AI项目2\桌面D6"
npm install
npm start
```

`npm install` 只需要在首次运行、依赖缺失或依赖发生变化时执行。平时启动只需要运行 `npm start`。PowerShell 窗口关闭后，开发运行版也会退出。

## 项目结构

```text
桌面D6/
├─ collectibles/       道具 PNG 图标目录
├─ resourcse/           D6 摆件视觉素材目录
├─ node_modules/        npm 安装生成的依赖目录
├─ index.html           摆件界面结构
├─ styles.css           摆件尺寸、位置、浮动和拖动区域样式
├─ renderer.js          界面点击、拖动和右键菜单事件
├─ preload.js           渲染页面与 Electron 主进程之间的安全接口
├─ main.js              主窗口、快捷方式处理、随机与恢复逻辑
├─ package.json         项目信息、启动命令和 Electron 依赖声明
├─ package-lock.json    npm 生成的依赖版本锁定文件
└─ README.md            项目说明
```

### `collectibles/`

存放用于替换桌面快捷方式图标的道具 PNG。目前程序只读取符合以下格式的文件：

```text
collectibles_数字_名称.png
```

例如：

```text
collectibles_001_thesadonion.png
collectibles_999_customitem.png
```

图标应使用带透明通道的 32×32 PNG。`placeholder.png`、`questionmark.png` 或其他不符合命名规则的图片不会进入随机池。

开发运行时，程序读取项目中的 `collectibles`。打包后，程序优先读取 `.exe` 旁边的 `collectibles` 文件夹，因此用户可以直接添加、替换或删除图标，不需要重新打包程序。

如果外置目录存在但其中没有有效图标，点击 D6 时会提示道具文件夹为空。

### `resourcse/`

这是当前使用的摆件素材目录。目录名目前就是 `resourcse`，代码和页面均按此名称引用。

| 文件 | 用途 |
| --- | --- |
| `dice.png` | D6 本体图片，同时是主要点击目标 |
| `pedestal.png` | D6 下方的道具底座 |
| `shadow.png` | 位于底座顶面的悬浮阴影 |

### `main.js`

Electron 主进程入口，负责：

- 创建 128×164 的透明无边框置顶窗口。
- 读取个人桌面和公共桌面中的 `.lnk` 快捷方式。
- 通过 Windows `WScript.Shell` 读取和修改快捷方式图标。
- 将 32×32 PNG 封装为 Windows 可使用的 ICO 文件。
- 在全体模式中处理所有可用快捷方式，也可以从菜单手动指定单个目标。
- 保存恢复数据和用户设置。
- 请求 Windows Shell 刷新图标显示。
- 构建右键菜单。

### `preload.js`

使用 Electron 的 `contextBridge` 向页面暴露有限接口：随机图标、恢复图标和打开右键菜单。页面没有直接获得 Node.js 文件系统权限。

### `renderer.js`

负责 D6 的页面交互：监听左键和右键、处理拖动，并在一次随机操作完成前防止重复点击。

### `index.html`

定义 D6、底座、阴影和拖动区域的页面结构。

### `styles.css`

负责透明窗口内的视觉布局，包括像素化放大、D6 与底座的相对位置、阴影大小、上下浮动动画、按压反馈以及底座拖动区域。

### `package.json` 与 `package-lock.json`

`package.json` 定义项目入口、`npm start` 命令和 Electron 依赖。`package-lock.json` 锁定实际安装的依赖版本，使不同机器安装出的开发环境尽量一致。

### `node_modules/`

由 `npm install` 自动生成，包含 Electron 和其他依赖。它不是手工维护的源码目录。缺少该目录时重新运行 `npm install` 即可。

## 图标随机流程

1. 扫描个人桌面和公共桌面中的 `.lnk` 文件。
2. 排除 D6 自身以及无法读取的快捷方式。
3. 根据当前操作选择全部快捷方式，或使用菜单手动指定一个快捷方式；手动目标会持续生效，直到取消。
4. 从 `collectibles` 中随机选择道具 PNG。
5. 将 PNG 封装为 ICO，并保存在当前配置的图标缓存目录中。
6. 记录快捷方式修改前的图标地址。
7. 修改快捷方式的 `IconLocation` 并通知 Windows 刷新图标。

## 运行数据

程序不会修改原始道具 PNG。设置和恢复数据保存在 Electron 用户数据目录中，生成的 ICO 保存在配置的缓存目录中：

| 内容 | 用途 |
| --- | --- |
| `settings.json` | 保存用户设置和当前手动目标 |
| `log/desktop-d6.log` | 开启“输出日志”后记录各环节耗时；打包后位于 EXE 旁的 `log` 文件夹 |
| `desktop-state.json` | 保存每个已修改快捷方式的默认图标和缓存文件记录 |
| `desktop-d6-cache/` | 默认的 ICO 缓存目录，位于程序安装目录 |

程序会优先使用安装目录下的默认缓存。若安装目录不可写（例如安装在受保护的 `Program Files`），会自动改用 Electron 用户数据目录下的 `desktop-d6-cache`，也可以从右键菜单手动指定其他位置。

生成的 ICO 不能在仍被快捷方式引用时删除，否则 Windows 可能显示空白图标。

性能日志以 UTF-8 JSON Lines 追加保存，每行包含时间、事件和毫秒耗时（`durationMs`），同一次操作的 `operationId` 相同。记录素材列表准备、缓存检查、目标读取、PNG 读取、ICO 转换和写入、恢复记录保存、后台排队等待、PowerShell 调用、快捷方式写入、刷新通知以及恢复/清理耗时。错误也会记录。

应用启动时会创建一个常驻 PowerShell 工作进程，并在显示 D6 前完成 `Add-Type` 编译和 `WScript.Shell` COM 初始化。之后的快捷方式读取、写入、恢复和 Explorer 刷新都复用这个进程；单图标模式会在同一个请求中完成写入和局部刷新，并缓存当前目标的快捷方式 COM 对象供连续随机复用。选择其他目标、切换全局模式、恢复或显式读取时会释放相应缓存。工作进程异常退出或请求超时时，程序会终止旧进程、重新初始化并重试一次。

开启日志后，`powershell.worker.ready` 记录一次性初始化总耗时以及 `nativeCompileMs`、`comCreateMs`；`powershell.worker.complete` 记录每个请求的通信总耗时、工作进程内部耗时和 `stages`。写入阶段包括是否命中缓存的 `cacheHit`、`shortcutOpenMs`、`propertySetMs`、`shortcutSaveMs`、重新打开并校验保存结果的 `verifyOpenMs`，刷新阶段包括 `memoryMs` 和 `notifyMs`。

单个模式的 `randomize.return` 只是点击请求返回；`shortcut.queue.complete` 才表示后台写入和刷新通知已完成。`operationElapsedMs` 是从操作开始到该日志事件的时间。Explorer 实际在屏幕上绘制完成的时间无法由这些通知确认，日志不代表屏幕更新延迟。嵌套步骤的耗时有重叠，不应全部相加。

性能日志先进入内存队列，再异步批量追加到文件，不阻塞图标操作。关闭日志后不再生成新记录，队列中已有记录仍会写完，已有日志保留；写入失败会在启动终端提示，图标操作继续执行。若希望记录启动预加载耗时，先勾选日志，再重启应用。

## 恢复机制与限制

- 每个快捷方式首次被 D6 修改时会保存默认状态；连续随机不会覆盖这份记录。
- 最近距离单点选择暂时停用；手动选择模式通过文件选择框指定目标，不依赖桌面坐标读取。
- 手动选择时会立即保存该快捷方式的默认图标和目标程序路径，但选择本身不会修改图标；之后左键点击 D6 只随机该目标；使用菜单中的“切换为全局随机”即可切回全局模式。
- “恢复桌面默认图标”会恢复所有仍有记录的快捷方式，并清理它们不再使用的生成图标。
- 切换缓存目录只影响之后生成的图标；旧缓存会保留到对应快捷方式恢复默认后再删除。
- 当前只处理 `.lnk` 应用快捷方式，不修改普通文件、文件夹、回收站、“此电脑”、任务栏或开始菜单图标。
- 某些图标可能受 Windows 图标缓存影响，需要短暂等待刷新。
- 删除或移动已经修改过的快捷方式后，该条目的恢复操作会被跳过。
- 建议首次测试时先使用少量临时快捷方式确认行为。

## 后续打包

计划生成 Windows 便携版或安装版。打包时需要让 `collectibles` 作为 `.exe` 旁边的外置目录发布，不能将其只封装进不可编辑的应用归档。这样用户无需安装 Node.js，也能双击启动并自由管理自己的道具图标。
